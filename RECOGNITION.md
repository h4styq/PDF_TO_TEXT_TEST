# Схема распознавания УПД / счёт-фактур

Цель — **улучшать общий конвейер**, а не добавлять отдельную логику под каждый PDF. Эталонные PDF (Дарт, Электроприбор, Электромонтаж, ЛинкМаг) — регрессионные тесты; новые документы должны обрабатываться теми же правилами.

## Поток данных

```
PDF → [Gemini PDF] → при 429 → [OCR.space] → плоский текст
                    ↓
         parseInvoiceData_
                    ↓
    шапка (продавец, основание, платёжный документ)
    таблица: pickBestOcrTable_ → normalizeGoodsTableRows_
```

## Таблица товаров (общее ядро)

1. **semanticMapGoodsRow_** — токены строки в канонические 15 граф УПД (ОКЕИ 796, шт, кол-во, цена, суммы, НДС, страна).
2. **repairScrambledOcrRow_** — локальные исправления «перепутанных» граф после OCR.
3. **mergeOcrContinuationRows_** — склейка обрывков наименования (GX, колодки и т.д.).
4. **normalizeGoodsTableRowOrderGeneric_** — порядок и тип строк **без ИНН контрагента**:
   - `classifyGoodsRowKind_`: `product` | `delivery` | `other` (наименование + величина сумм).
   - `goodsRowDocumentRank_`: товар раньше доставки.
   - дубль наименования в блоке УПД → вторая строка как доставка (`inferDeliveryRowFromFlatOcr_`).
5. **repairGenericMappedRow_** — для любой строки:
   - расширение наименования из плоского OCR (`expandProductNameFromFlatOcr_`);
   - доставка: суммы из фрагмента + плейсхолдеры `-` / `--`;
   - товар: `repairOcrMetricsFromSourceLine_`, `finalizeRowVatTotalsGeneric_` (в графе «всего» не оставлять только сумму без НДС).
6. **applyVendorDocumentRepairs_** — **тонкий слой** только если в тексте явные маркеры эталонного контрагента (Электромонтаж, ЛинкМаг). Со временем этот слой должен сужаться.

## Выбор источника таблицы OCR

`pickBestOcrTable_` сравнивает:

- таблицу из **блока УПД** в тексте;
- **построчную эвристику** (`parseOcrProductRowsOnly_`).

Штраф блоку за **дублирующиеся наименования** в соседних строках (типичная ошибка OCR: две строки с одним товаром вместо «товар + доставка»).

## Внешние API

- **Gemini** — основной путь для PDF (структура `===HEADER===` / `===TABLE===` при успехе).
- **OCR.space** — запасной путь; для файлов >1 МБ возможен временный доступ по ссылке Drive.

## Эталоны

`GOLDEN_EXPECTED_BY_FILE` + меню «Сверить … с эталоном» — только проверка, не источник данных в проде.

При добавлении нового эталона:

1. Сначала проверить, помогает ли **общее** правило (классификация, дубли, НДС, доставка СДЭК/«Доставка товара»).
2. Только если нет — минимальное расширение `applyVendorDocumentRepairs_` или подсказка в `expandProductNameFromFlatOcr_` / `isDeliveryServiceRow_`.
